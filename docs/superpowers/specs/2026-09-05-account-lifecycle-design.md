# 注册审批与账号注销申请设计

日期：2026-09-05。状态：方向已获用户同意；本文件等待书面设计确认，尚未实施。

## 1. 目标与范围

为 Love English 增加 App 内注册申请和注销申请，由 senior-platform 管理后台处理。注册可以批准或拒绝；注销是核验后完成用户请求，不是管理员任意决定是否允许退出。

账号是 iOS 与网页共用的 senior 平台账号。注销确认页必须说明：删除会影响网页端登录及该账号的词汇、练习、作文、学习计划等数据，不只影响英语 App。设计批准只授权开发该能力，不授权删除任何现有生产账号。

本阶段改动范围：iOS 客户端、相关后端 API／数据库迁移、现有网页注册响应处理和用户管理页。保留既有活跃用户及审核专用账号；不修改其他学习功能，不迁移到独立身份系统。隐私入口、隐私清单和上架文案需按最终数据流同步更新。

## 2. 已核查的现状

- `englishwords/app/Sources/Features/Auth/LoginView.swift` 只有登录，提示去网页注册。
- `senior-platform/backend/app/api/auth.py` 已有注册、登录、短信、地区和个人资料接口。注册在短信开启且验证码有效时自动激活，否则等待管理员；当前不符合“所有自助注册均待批准”的目标。
- `User.is_active` 与 `last_login_at` 被用于推断待审核和禁用，无法可靠表达拒绝或注销状态。
- `frontend/web/src/pages/admin/Users.tsx` 已有启用、禁用和删除入口，可扩展现有后台，不另建管理系统。
- 多个学习表依赖 `users.id`；作文引导消息、辅导消息等还存在间接依赖。现有管理员删除接口直接删除 User，不能作为完整注销执行器。
- 上传文件另存于配置的上传目录。删除数据库行不等于删除图片／附件。
- 旧 App 的登录会根据服务端账号有效性决定是否可用；迁移必须保持旧版普通登录兼容。

以上是本地代码证据，不代表已经确认生产数据库内容、短信可用性和备份配置。

## 3. 方案选择

采用“原生申请界面 + 共用后端状态 + 后台人工触发可靠删除”。用户操作连贯，复用当前账号体系；代价是增加状态、处理队列和后台职责。

另两种方案不采用：

- 全自动立即注销：减少人工运营，但不符合本轮希望由后台处理的选择，且目前跨功能数据清理尚未建立。
- 只提供客服邮箱：开发量小，但不作为本 App 的注销主流程；用户应能直接在 App 发起并查看处理状态。

Apple 明确允许人工处理，但要求说明处理耗时、实际完成删除并向用户确认。依据：[账号删除指引](https://developer.apple.com/support/offering-account-deletion-in-your-app/)。该设计不是审核通过保证。

## 4. 注册与审批

### 用户流程

登录页新增“申请账号”，原生表单提交手机号、密码、姓名和有效地区；年级／学校沿用平台可选字段。不增加身份证、头像或其他非必要资料。显示隐私政策入口及明确的申请说明。

注册成功只返回待审核状态，不签发学习接口令牌，也不跳转主页面。申请人可在 App 凭原手机号和密码查看申请状态或删除尚未批准的账号资料。拒绝后显示经过限制的用户可见理由；后台内部备注不返回用户。

新自助注册无论来自网页还是 iOS、短信是否开启，都需管理员批准。管理员直接创建账号仍可立即启用。已有账号不重新审批；网页注册页同步展示新的待审核结果。批准、拒绝与恢复申请均要求管理员权限并记录事件。

### 状态与兼容

增加显式账号状态：`pending_approval`、`active`、`rejected`、`disabled`、`deleting`。`is_active` 暂作为兼容字段，由统一服务更新，不允许接口各自赋值。

迁移：现有启用用户转 `active`；现有禁用用户保守转 `disabled`，不依据“从未登录”自动认定申请人身份。后台列出历史禁用记录供管理员手工分类，避免误激活。所有单条／批量启用禁用入口必须经过同一状态校验，不能重新启用 `deleting` 账号。

### 认证与防滥用

保留密码强度、手机号格式、地区有效性及服务端限流；密码仅存哈希，不记入日志。短信验证与管理员审批是独立检查，验证码通过不授予使用资格。

不将现有静态 `X-App-Client` 标记扩展为注册或注销安全凭据。注册使用现有服务端验证的 Turnstile；iOS 如需挑战界面，只加载运营方 HTTPS 验证页，通过受限消息桥取回短期验证结果，不将密码或登录令牌放到 URL。网页继续原有验证方式。验证码／挑战校验失败不降级绕过，需测试真机与生产域名可用性后开放。

新增受限状态查询会话，仅允许查看本人申请状态和提交本人删除申请；不允许调用学习／管理员接口。待审核、被拒绝或禁用用户也必须能通过重新认证访问自身数据删除入口。未知账号与错误密码统一响应；正确认证后才返回具体账号状态。

## 5. 注销申请与后台处理

### 用户流程

“我的 → 账号与隐私 → 注销账号”。重新验证密码，展示整个平台影响、处理期限、保留数据说明及未同步数据提示，再二次确认。理由可选，不能强制填写作为门槛。

提交成功生成注销申请和只读回执凭据。App 保存回执到 Keychain，不把明文回执、密码或令牌放入日志。用户能查看收到申请、处理中、需要处理的异常、已完成；提供明确的完成确认，不把登录失败当作完成通知。

回执凭据与学习登录令牌严格隔离；服务端仅存回执哈希。回执查询不返回手机号、姓名或学习内容，也不能用于撤销或操作其他账号。重装后可在账号尚存在时通过重新认证重新获取状态；账号删除后仍可用此前回执查看完成确认。上架说明准确告知此回执机制，不承诺尚未配置的短信或邮件通知。

### 状态与并发

注销申请状态：`requested → processing → completed`；执行失败转 `failed`，管理员可重试。同一账号最多一条未完成申请；重复提交和执行返回已有状态，不重复清理。没有管理员“不同意注销”按钮。

`requested` 期间保持原有账号权限，不将递交申请等同于删除；页面显示进度。处理开始后账号转 `deleting`，拒绝新的业务操作及刷新令牌。执行器必须协调正在进行的写入、后台任务和文件生成，防止删除后重新写回数据。不能只靠切换 `is_active` 处理并发。

进入 `processing` 前可由本人重新认证后撤回申请；撤回记录独立标记为 `cancelled`。执行开始后不可撤回或恢复；失败时保持受限账号和待重试任务，不自动启用、不显示成功。

管理员可核验账号、查看数据类别与影响、触发处理、重试失败。界面区分“注册批准”和“执行注销”，不沿用容易误解的“注销审批通过”。超过承诺期限的申请需醒目标记并进入运营处理，不允许无限期挂起。

### 删除执行器

使用明确的关联清单和可重入执行器，不采用数据库全表删除或按目录递归清空。数据库删除阶段使用事务；外部文件清理通过持久任务记录执行，成功后才能标记注销完成。

处理范围包括：词汇收藏／进度／答题日志、练习与测验、错题／薄弱点、考试、作文及引导消息、辅导会话及消息、学习计划及任务、打卡／周报、推送订阅、用户生成图片及附件、账号身份信息，以及涉及该用户的缓存和后台任务。共享词典、公共文章、题库和其他用户数据不删除。

先枚举间接依赖和文件引用，验证目标路径属于该用户且位于允许的上传根目录；共享文件不得误删，不能删除用户内容中任意外部 URL。无法确认归属时记录失败供处理，不伪报完成。

审计中既有的手机号、姓名、用户 ID、target ID 和嵌套详情均须纳入清理／最小化检查，不能仅将外键设空。保留不含被删用户身份的操作计数、执行时间和错误类别。支付、法定安全记录及备份保留按发布前确认的具体规则执行，不能任意永久保留，也不能未经核实删除依法须保留的数据。

删除结束后清除账号、令牌访问能力及 iOS 本地学习缓存、待同步记录、打卡和个人设置；其他设备在明确的账号终止响应下清理本地数据。普通网络失败或通用 401 不触发不可恢复的本地数据清除。旧版 App 不能远程保证清缓存，政策不承诺删除未联网设备上的所有副本。

## 6. 建议接口边界

路径为本设计的新接口约定，当前并不存在：

| 接口 | 责任 |
| --- | --- |
| `POST /api/auth/register` | 复用并修正为自助申请；稳定返回 pending 状态 |
| `POST /api/account/session` | 重新认证后签发短期、仅账号管理权限的会话 |
| `GET /api/account/status` | 查看本人注册／注销状态，不开放学习数据 |
| `POST /api/account/deletion-requests` | 认证、确认范围及政策版本后幂等创建申请 |
| `POST /api/account/deletion-requests/cancel` | 重新认证后撤回尚未开始执行的本人申请 |
| `POST /api/account/deletion-receipt/status` | 凭回执只读查询结果；凭据放请求体且不记录请求体 |
| `POST /api/admin/users/{id}/registration-decision` | 批准／拒绝注册，校验目标状态 |
| `GET /api/admin/deletion-requests` | 分页查看待处理、失败、超时记录 |
| `POST /api/admin/deletion-requests/{id}/process` | 幂等调度执行器，不直接宣称删除成功 |

普通账号管理 API 不接受客户端指定其他用户 ID。访问、刷新、账号管理和回执令牌按类型隔离；统一返回机器可读错误码和可理解的中文说明。管理员操作校验当前管理员身份、角色和账号状态，拒绝使用刷新令牌冒充访问令牌。

## 7. 验证与上线顺序

1. 在隔离测试数据库验证状态迁移，已有活跃账号不受影响，历史禁用用户不误启用。
2. 后端测试覆盖注册等待、批准、拒绝、重复请求、短信开关、验证码失败、越权、限流、所有令牌类型及状态约束；网页路径不能绕过审批。
3. 用含全部关联数据和附件的合成用户验证注销，包含并发写入、事务回滚、外部文件失败重试；校验其他用户及公共内容完整，旧访问／刷新令牌均失效。
4. iOS 测试覆盖表单、待审核、拒绝、注销影响确认、离线失败、重复点击、处理中、回执、完成清理和权限隔离；后台测试验证处理状态与失败重试。
5. 在非生产环境完成网页和 App 端到端测试；不使用审核账号或真实用户做删除测试。全流程通过后才安排生产迁移、后端发布、新 Archive 与截图更新，并分别记录验证结果。

这不是本轮实现任务清单；书面设计确认后再拆成可并行开发和独立审阅的任务。

## 8. 发布前必须确认的运营条件

以下不阻碍编写隔离环境代码，但未确认时禁止对外开放申请或定稿政策：

- 注销处理期限建议为 **7 个自然日内**，这是待运营方确认的服务承诺，不是 Apple 指定时限。配置须显式设置；不设静默默认值。申请保存提交当时的截止时间，后续配置变更不能延长旧申请期限。
- 注册申请、拒绝记录、注销回执、安全日志、支付记录和备份分别确定保留规则、执行责任人及清理验证方式。没有经确认的规则不得发布“全部立即删除”等声明。
- 确认运营主体、公开政策／支持地址、短信及验证服务的真实配置。回执查询服务需在账号已删后仍可用；确认其保留期限并告知用户。
- 验证备份恢复流程不会重新激活已注销账号；恢复前重放删除清单，清单本身按最小化和限期策略管理。
- 审核账号保持有效且已批准；审核说明提供完整操作步骤，不把人工注册审批作为审核人员无法体验功能的障碍。
